## 2025-10-27 - Frontend Preview Memoization and Callback Optimization
**Learning:** In a highly interactive app where users type frequently into an editor on one side of a split pane, having computationally expensive operations (like parsing Markdown and rendering KaTeX) in the other pane's component can cause significant performance bottlenecks if they share state (like `pages` state in `App.tsx`) and re-render together on every keystroke. Although `MemoizedMarkdown` was implemented in `Preview.tsx`, the `Preview` component itself was re-rendering unnecessarily on every change to `inputText` because its parent `App` re-rendered and passed down new inline callback references (`onUpdateMarkdown`, `onToggleEditMarkdown`) and new array references (`currentPage.textBoxes || []`). This defeats partial memoization downstream.
**Action:** Always wrap parent callbacks in `useCallback` when passing them down to expensive memoized child components, and never pass inline array literals `[]` as props in rendering loops (use a static constant like `EMPTY_TEXT_BOXES` instead). Also, ensure the computationally expensive component itself is wrapped in `React.memo()`.
