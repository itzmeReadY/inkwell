## 2025-02-25 - Prevent SSRF and LFI in Headless Browser PDF Generation
**Vulnerability:** The application used Playwright's headless Chromium to render user-controlled HTML to PDF without restricting network access. This could allow an attacker to embed external links (like file:///etc/passwd or http://internal-service) in image/script tags, leading to Server-Side Request Forgery (SSRF) and Local File Inclusion (LFI).
**Learning:** By default, headless browsers will attempt to fetch all resources referenced in the HTML document. When generating PDFs from user-provided content, this behavior poses a severe security risk if the environment can access sensitive files or internal network endpoints.
**Prevention:** Always implement a strict allowlist for network requests using `page.route` when using a headless browser to process untrusted content. Block everything by default and only permit known-safe origins (e.g., specific CDNs, fonts) and schemes (e.g., `data:` for embedded assets).
