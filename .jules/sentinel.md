
## 2024-10-08 - SSRF and XSS in Playwright PDF Rendering
**Vulnerability:** The application was vulnerable to Server-Side Request Forgery (SSRF) and Cross-Site Scripting (XSS) due to rendering un-sanitized HTML in a headless Playwright instance. Attackers could inject arbitrary `<script>` tags or utilize HTML features (like `<img src="...">` or `fetch(...)`) to perform internal requests or exfiltrate local files from the server since the renderer was run directly on the backend.
**Learning:** Even though the frontend handles generating the markdown, the backend compiles it into HTML and passes it to Playwright. In server-side headless browser generation, injecting arbitrary HTML essentially allows an attacker to execute Javascript in the context of the server, opening doors to local file disclosure or SSRF.
**Prevention:** Always implement a strict Content Security Policy (CSP) when passing dynamically generated or user-controlled HTML to headless browsers like Playwright. Setting `default-src 'none'`, restricting `connect-src`, and minimizing `script-src` to explicitly allowed origins ensures injected scripts cannot connect to local networks, read local files, or fetch sensitive endpoints.
